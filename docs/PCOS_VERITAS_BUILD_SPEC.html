PCOS Veritas Engine — Build Spec v1

What to build, in what order, with which modules — derived from the open-source research and hardened against every failure mode the Vigo County pilot actually produced. Schema and stage contracts are written and committed; this document is the map to them.
Buildable now · 2026-08-27 · repo: pcos-verified-community-news/engine

The research report surveys the state of the art: ClaimBuster scores check-worthiness, SAFE and FActScore decompose and verify, OpenFactCheck wires solvers together as plugins, FactReasoner aggregates conflicting evidence probabilistically, Perplexica/Vane plans research over a private SearXNG. We should adopt all of it. None of it is our moat — and none of it survived contact with a real county record without the four safeguards below.

The one-paragraph thesis

Every framework in the literature answers "is this statement true?" and then forgets everything. PCOS answers two questions nobody else does — "is this person saying the same thing in every room?" and "can you still prove it a year from now?" The published modules are commodity parts. The custody chain, the resolution layer, the congruence index, and the fairness gates are the product, and they are what a lawyer will ask about.

1 · What the pilot changed about the design

Four failure modes appeared in a single day of real work on one subject. Each would have produced a confident, quotable falsehood about a living person weeks before an election. They are now blocked by types, not by discipline.

The gate, in code — already written and tested

def gate(u: Utterance) -> VerdictEligible:
    """The single chokepoint. Everything downstream requires this type."""
    if u.speaker_conf is not SpeakerConfidence.CONFIRMED:
        raise GateError(f"speaker {u.speaker_conf.value} at {u.anchor}: "
                        "cannot attribute to a named person")
    if u.mode is not SpeechMode.ASSERTION:
        raise GateError(f"mode={u.mode.value} at {u.anchor}: "
                        "only plain assertions receive verdicts")
    return VerdictEligible(utterance=u)

Run against the pilot's real failures: BLOCKED — "speaker unresolved at 0:11:44" (the Kearns/Ellis trap) · BLOCKED — "mode=satire at 0:11:44" (the skit trap) · PASSES — clean assertion. A VerdictRecord cannot be constructed without a VerdictEligible, so no downstream code can route around this.

3 · Layer map — onto the PCOS 11-layer architecture

The research report describes the governed-intelligence stack the engine slots into. Mapping the pipeline to it rather than inventing a parallel architecture:

L0–L1

Hardware & network. Fleet nodes; local GPU for triage and ASR (verified available: RTX 3060, 16 cores, 62 GB RAM, Ollama with Qwen resident).

L4

QSurface — semantic packet transport. Sealed artifacts, verdicts, and congruence findings travel as semantic packets with a cryptographic audit chain: hash-linked, tamper-evident, traceable to origin. This is the custody backbone, already proven in eDNA.

L5

Semantic. Claim decomposition, entity/role resolution, mode classification, topic assignment — the meaning layer where a claim is matched to the agents able to verify it.

L6

Application. Stage execution and workflow: acquire → render → resolve → extract → retrieve → reason.

L9

Orchestration — multi-provider verification. No single model produces a final answer alone. Claude and Qwen cross-check each other; the adversary pass runs on a different model than the drafting pass. Disagreement is a signal, not an error.

L10

Mothership — governance. The publication gates, the fairness policy, the symmetry rule, the retention and correction policy.

Resolving the one genuine contradiction in the research

The report advocates probabilistic reasoning (FactReasoner's Markov network over atoms and evidence) in one section, and in another insists on deterministic, rule-governed calculations where every final score is reproducible and defensible. Both are right, and the resolution is our existing pattern: probabilistic MODEL, deterministic EXECUTION. The reasoner may weigh conflicting evidence probabilistically, but the evidence set is frozen and hashed (verdict.inputs_hash), the model and prompt are pinned (model_ref), and replaying the same inputs must reproduce the same verdict byte-for-byte. Confidence is calibrated; the computation is replayable. That is exactly how eDNA's as-of scoring already works.

-- A publication cannot go live unless every finding has a reply record

Other load-bearing columns: artifact.jurisdiction_scope (what a source does not cover), rendition.is_machine_text (OCR/ASR text is a search index, never a quotation source), evidence.stance='mitigates' (what the adversary pass finds), evidence.source_tier (tier 5 social proves a claim was made, never that it is true), verdict.supersedes_id (corrections are new rows — the chain is append-only).

The sleeper asset: a roll-call vote parser

County minutes encode votes as repeating prose — "Name — aye; Name — nay;" — with movers and seconders named inline. The meeting → agenda_item → vote tables turn that into queryable structured data, including is_seconder (which is how we found that the subject seconded the budget he publicly calls wasteful). Point this at every county in Indiana and you have a vote database nobody else has — independently valuable regardless of where the news product goes.

8 · Risks that belong on the build plan, not in a footnote

Legal exposure is the real risk — not technical failure

We publish findings about named living people, and one day of pilot work produced four distinct ways to generate a confident falsehood. Before any public launch: media-liability insurance, a standing media-law attorney, a written pre-publication review, and the reply gate enforced in code (it is). Budget these in P1, not "later."

Licensing

ClaimBuster's claim-spotter is GPL-3.0 — reimplement the published method or isolate it behind a network boundary; counsel confirms before a line is used. Llama 3's licence is not open source — default to Qwen (Apache-2.0) and Claude, and verify each specific weight's licence at adoption.

The source research needs fact-checking — verify every module at its repo

The report contradicts itself on DeepMind's SAFE: one section gives a full technical account, a later section states no such project exists. (SAFE is real.) It also asserts a "Vane, rebranded from Perplexica in March 2026" and cites Qwen versions and parameter counts that are unverified here. Every module in §4 gets confirmed at its source repository and licence file before adoption. A research document about automated fact-checking that fails its own standard is the best possible argument for building this engine — and a standing reminder that plausible and sourced are different things.

Two policy decisions to make before P1 ships

Symmetry. If the first published subject is a Republican, the second is a Democrat, and the standard applied must be visibly identical. This is a product requirement — the engine's only asset is being trusted by people who dislike its findings.

Source disclosure. Adopt now: always disclose that a story came from a tip, and always state whether the tipster's interest was checked. Free from article one; ruinous to retrofit.
